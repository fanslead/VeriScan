# VeriScan 管理后台体验方向

## 产品语境

用户是内容安全运营、平台管理员和安全负责人。后台的核心工作不是“看漂亮报表”，而是快速回答三件事：现在哪里有风险、哪个应用受影响、下一步能做什么。

## 视觉系统

主题名：**校准台（Calibration Desk）**。

- `Ink` `#101828`：导航与高密度信息；
- `Graphite` `#344054`：正文和辅助层级；
- `Frost` `#F4F6F5`：工作区底色；
- `Paper` `#FFFFFF`：内容表面；
- `Verdict Red` `#D84A3A`：拒绝与高风险；
- `Evidence Teal` `#127C72`：通过、证据与已验证状态。

中文正文使用 `Noto Sans SC / Source Han Sans SC / PingFang SC`，数字、Key 前缀和延迟使用 `IBM Plex Mono / SFMono-Regular`。不用大面积渐变，不把所有区块都做成同形卡片。

## 布局签名

页面的记忆点是“判定轨”：一条贯穿主要工作区的细窄状态轨，将规则、AI、最终结论和证据按真实处理顺序串联。它只出现在审核详情和总览的实时摘要中，其余界面保持安静。

```text
┌──────────┬──────────────────────────────────────────────┐
│ 明鉴     │ 当前应用 / 时间范围             快速操作     │
│ 总览     ├──────────────┬───────────────────────────────┤
│ 应用     │ 风险态势     │ 判定轨                        │
│ 审核记录 │ 不是四张卡片 │ 规则 ─ AI ─ 结果 ─ 证据      │
│ AI 配置  ├──────────────┴───────────────────────────────┤
│ 规则     │ 需要处理的变化与最近记录                     │
│ 审计     │                                               │
└──────────┴───────────────────────────────────────────────┘
```

导航使用紧凑深色轨道，内容区保持浅色、清晰分组和足够留白。宽屏优先展示上下文，窄屏将侧栏收起并保持主操作可见。

## 交互基线

- 创建 API Key 后只显示一次；关闭前必须明确确认已保存，支持复制反馈但不自动下载明文。
- 撤销、停用、发布和回滚必须解释影响范围，并要求有意义的原因。
- `review` 文案统一为“建议复核”，说明由调用方处理，后台不出现“待领取”或“去审核”。
- 空状态给出下一步动作；错误说明可恢复方式；列表筛选写入 URL，刷新后保持。
- 所有异步操作提供局部 loading，避免整页遮罩；成功反馈使用动作完成式语言。
- 键盘焦点可见，颜色不是唯一状态信号，尊重 `prefers-reduced-motion`。
- 页面不得显示协议名、数据库字段、内部错误堆栈等技术性提示；技术详情仅出现在受控诊断视图。

## 自我审查

这不是通用 SaaS 仪表盘：去掉“渐变欢迎横幅 + 四张大指标卡”的模板组合，把视觉风险投入在判定轨和高密度证据组织上。所有装饰必须解释状态或流程，否则删除。
