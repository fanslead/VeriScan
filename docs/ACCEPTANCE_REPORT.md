# VeriScan 本地交付验收报告

日期：2026-09-01

范围：当前仓库、本机开发环境与隔离 Docker 容器；不代表生产环境上线验收。

## 1. 结论

当前版本已经形成可运行的生产候选基线：应用与独立 API Key、同步/异步/自动批量审核、不可变规则版本、关键词/常见格式/组合条件、三种外部 AI 协议、管理后台、审核记录、按应用/Key 统计、Outbox、审计、混合缓存、OpenTelemetry、迁移任务、liveness/readiness 和非 root 容器镜像均有代码与自动化或真实容器证据。

但当前结论不是“可直接无条件上线”。真实供应商、生产 OIDC/TLS、备份恢复、故障演练和整链路容量仍需在目标环境验收；技术方案里的整体 QPS、AI 延迟和准确率仍是目标值，不能用本报告中的进程内规则基线替代。

## 3. 规则引擎本机基线

命令：

```bash
dotnet run --project tests/performance/RuleEngine.Baseline/RuleEngine.Baseline.csproj \
  --configuration Release -- 10000 20000
```

环境：Apple M1 Max、10 个可见处理器、64 GiB 内存、Darwin arm64、.NET 10.0.11。输入为 10,000 条词规则、32 字符文本、20,000 次热运行。

| 指标         |          结果 |
| ------------ | ------------: |
| 编译规则版本 |     28.328 ms |
| 单次均值     |      3.384 μs |
| P95          |      3.542 μs |
| P99          |      5.291 μs |
| 进程内吞吐   | 295,486 ops/s |
| 单次分配     |   1,432 bytes |

该结果只衡量已经编译并按不可变版本缓存的多模式词匹配与判定，不含 HTTP、PostgreSQL、API Key、JSON、日志、外部 AI 或网络。它不能证明“整链路 QPS 1500+”，也不能与二级 AI 延迟相加后直接推导生产容量。

## 4. 真实容器审核与过载证据

真实容器纵向链路得到以下结果：

- 同步批次 HTTP 200，硬拒绝、组合条件建议复核和正则证据均按规则终结；
- 异步批次 HTTP 202，第二次轮询完成，决定为 `reject/review`；
- 相同幂等键和相同正文返回同一 `requestId`，正文变化返回 HTTP 409；
- 用量接口记录 2 个新批次，记录页含 7 个 item，审计接口含 5 个治理事件；
- 认证前入口并发上限为 64。100 请求 / 并发 16 的短基线为 817.01 请求/秒，P95 24.71 ms、P99 25.17 ms、0 错误；
- 1,200 请求 / 并发 128 的突发场景得到 270 个 HTTP 200、930 个 HTTP 429、0 客户端错误，API 容器保持 healthy 且重启次数为 0。

突发场景验证的是有界背压，不是成功吞吐成绩。此前无入口闸门时同级突发可触发退出码 139；该失败已转化为可观测、可重试的 429，但仍需在目标资源上做三次 60 分钟长稳和故障注入。

## 5. 上线前必须补充的目标环境门禁

- 使用目标 OIDC、TLS、域名、密钥系统和网络策略完成认证与 SSRF 边界验收；
- 对每个实际 AI Provider 执行合成请求，核对 schema、超时、429/5xx、费用与数据出境要求；
- 用匿名化代表性数据执行完整 HTTP 压测，分别测规则直拒、AI 路由和 Provider 故障三种曲线；
- 演练 PostgreSQL 备份恢复、迁移回滚策略、Redis 故障、Provider 超时风暴和 Key 泄露撤销；
- 建立独立标注评测集后再发布准确率、召回率和阈值，不能沿用方案估算；
- 对容器基础镜像使用发布时固定 digest，并执行镜像、依赖、许可证和 SBOM 扫描。

## 6. 明确保留的后续能力

当前版本已完成组合规则、受控正则、异步批次、任务租约和 Outbox；没有把 RAG、多模态、Webhook 投递、双人审批、灰度比例、主动学习和多租户计费伪装成已完成。`review` 仍是 VeriScan 的机器审核终态，只返回调用方并记录事实，不建设平台人工复审队列。
